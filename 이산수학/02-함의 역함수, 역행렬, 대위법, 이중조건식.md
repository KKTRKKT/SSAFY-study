## 1) 이번 영상에서 다루는 것

1. **함의(Implication)**: `P → Q` (if P then Q)
2. 함의에서 파생되는 3가지:

   * **대우(Contrapositive)**: `¬Q → ¬P`
   * **역(Converse)**: `Q → P`
   * **이(Inverse)**: `¬P → ¬Q`
3. **쌍조건문(Biconditional)**: `P ↔ Q` (P iff Q)
4. `P ↔ Q`가 어떤 **복합명제**와 동치인지

---

## 2) 함의(Implication) `P → Q`의 의미

### 2.1 정의(형식적 의미)

`P → Q`는 “P이면 Q이다”라는 조건문입니다.

* **P**: 조건(가정, hypothesis / antecedent)
* **Q**: 결론(conclusion / consequent)

중요 포인트:

* 이 문장은 **P가 참인 경우에만** Q에 대해 “보장”을 요구합니다.
* **P가 거짓이면**, 이 문장은 Q에 대해 아무것도 약속하지 않습니다.

---

## 3) 함의의 진리표와 “헷갈리는 줄” 설명

`P`와 `Q`가 2개이므로 가능한 조합은 4개(= 2²)입니다.

| P | Q | P → Q |
| - | - | ----- |
| T | T | T     |
| T | F | F     |
| F | T | T     |
| F | F | T     |

### 3.1 왜 `T → F`만 거짓인가?

`P → Q`는 “P가 참이라면 Q도 참이어야 한다”는 **약속**입니다.

* P가 참인데 Q가 거짓이면 약속 위반 → **거짓**
* 그 외는 약속을 위반했다고 말할 근거가 없음 → **참**

### 3.2 가장 헷갈리는 케이스: `F → T`가 왜 참인가?

예시로 영상처럼 잡겠습니다.

* P: “휴일이다”
* Q: “가게가 문을 닫는다”
* 명제: “휴일이면 가게는 문을 닫는다” = `P → Q`

이제 **휴일이 아닌 날(F)**에 가게가 닫았다고 해서(T),
이 조건문이 틀렸다고 할 수 있나요?

* 조건문은 “휴일인 경우에 닫는다”만 말합니다.
* “휴일이 아닌데도 닫는다”는 조건문이 금지한 적이 없습니다.
* 따라서 위반이 아니라서 **참**으로 둡니다.

이 현상을 논리에서는 **공허한 참(vacuous truth)**이라고 부릅니다.

* “전제가 거짓이면 함의는 참”이라는 규칙이 여기서 나옵니다.

### 3.3 기억 팁(시험용)

`P → Q`는 **오직 한 줄만 거짓**입니다.

* **P가 T이고 Q가 F일 때만 F**
* 나머지 3줄은 전부 T

---

## 4) Converse / Inverse / Contrapositive

원래 함의:

* **원명제**: `P → Q`

이것으로부터 3개를 만듭니다.

### 4.1 역(Converse)

* **정의**: `Q → P`
* “순서를 바꾼 것”

### 4.2 이(Inverse)

* **정의**: `¬P → ¬Q`
* “둘 다 부정한 것”

### 4.3 대우(Contrapositive) ⭐

* **정의**: `¬Q → ¬P`
* “순서를 바꾸고 둘 다 부정”

---

## 5) 예제로 완전히 정리하기 (영상의 ‘비가 오면…’ 예시)

원문을 “if-then” 형태로 먼저 정리하는 게 핵심입니다.

* 문장: “비가 오는 것은 내가 시내에 안 가는 충분조건이다”
* 자연스러운 if-then 변환:

  * **비가 오면 시내에 가지 않는다**
* P: “비가 온다”
* Q: “시내에 가지 않는다”

### 5.1 원명제

* `P → Q`: 비가 오면 시내에 가지 않는다.

### 5.2 역(Converse)

* `Q → P`: 시내에 가지 않으면 비가 온다.

### 5.3 이(Inverse)

* `¬P → ¬Q`: 비가 오지 않으면 시내에 간다.
  (Q가 “가지 않는다”였으므로 ¬Q는 “간다”)

### 5.4 대우(Contrapositive) ⭐

* `¬Q → ¬P`: 시내에 가면 비가 오지 않는다.

---

## 6) “대우는 원명제와 항상 같은 진리값”의 의미

핵심 사실:

* `P → Q` 와 `¬Q → ¬P` 는 **논리적으로 동치(equivalent)** 입니다.
* 즉, **항상 같은 진리표**를 가집니다.
* 따라서 원명제가 참이면 대우도 참, 원명제가 거짓이면 대우도 거짓입니다.

왜 중요하냐?

* 수학적 증명에서 “직접 증명(P→Q)”이 어려우면,
  **대우(¬Q→¬P)**로 바꿔서 증명하는 경우가 매우 많습니다.

---

## 7) 반면 역/이는 원명제와 동치가 아니다 (하지만 서로는 동치)

중요한 구조:

* **원명제** `P → Q` 와 **대우** `¬Q → ¬P` 는 동치
* **역** `Q → P` 와 **이** `¬P → ¬Q` 는 서로 동치
* 하지만 **원명제 ↔ 역** 은 일반적으로 동치가 아닙니다.

즉:

* `P → Q  ≡  ¬Q → ¬P`  (항상 참)
* `Q → P  ≡  ¬P → ¬Q`  (항상 참)
* `P → Q  ≢  Q → P`     (대체로 다름)

### 직관 예시(자주 쓰는 반례)

* P: “비가 온다”
* Q: “땅이 젖는다”
* `P → Q`: 비가 오면 땅이 젖는다 (대체로 참)
* `Q → P`: 땅이 젖으면 비가 온다 (스프링클러 등으로 거짓 가능)

---

## 8) 두 번째 연습문제(“숙제하면 교수님이 행복”) 정리

문장: “숙제를 하면 교수님이 행복하다” 형태로 다시 쓰면 명확합니다.

* P: “숙제를 완료한다”
* Q: “교수님이 행복하다”

원명제:

* `P → Q`: 숙제를 완료하면 교수님이 행복하다.

역:

* `Q → P`: 교수님이 행복하면 숙제를 완료했다.

이:

* `¬P → ¬Q`: 숙제를 완료하지 않으면 교수님이 행복하지 않다.

대우:

* `¬Q → ¬P`: 교수님이 행복하지 않으면 숙제를 완료하지 않았다.

> 실무적으로도 “원문을 if-then으로 정확히 정규화한 뒤” 변형하는 게 가장 안전합니다.

---

## 9) 쌍조건문(Biconditional) `P ↔ Q`

### 9.1 의미

`P ↔ Q`는 “P이면 Q이고, Q이면 P이다”입니다.
즉 **양방향 조건**입니다.

* “P는 Q일 필요충분조건이다”
* “P iff Q (if and only if)”

### 9.2 진리표

`P ↔ Q`는 **둘의 진리값이 같을 때만 참**입니다.

| P | Q | P ↔ Q |
| - | - | ----- |
| T | T | T     |
| T | F | F     |
| F | T | F     |
| F | F | T     |

---

## 10) 핵심 결론: `P ↔ Q`는 복합명제로 표현 가능

영상에서 다음 동치를 보여줍니다.

### 10.1 가장 표준 동치

[
P \leftrightarrow Q \equiv (P \to Q) \land (Q \to P)
]

말로 풀면:

* “P iff Q”는
* “(P이면 Q) 그리고 (Q이면 P)”와 같다.

### 10.2 추가로 많이 쓰는 다른 형태(참고)

[
P \leftrightarrow Q \equiv (P \land Q) \lor (\neg P \land \neg Q)
]
즉:

* 둘 다 참이거나
* 둘 다 거짓이면 참

---

## 11) 진리표를 “3구역”으로 나누는 이유(영상의 마지막 부분)

복합명제가 길어지면 한 번에 계산하기 어렵습니다. 그래서 진리표를 실무적으로 이렇게 구성합니다.

1. **좌측**: P, Q 모든 조합(기본 4줄)
2. **중간**: 중간 계산(예: P→Q, Q→P 같은 부품)
3. **우측**: 최종 결합(예: (P→Q)∧(Q→P))

이 방식은 이후 “동치 검증”에도 그대로 쓰입니다.

* 두 명제의 최종 열이 완전히 같으면 **동치**입니다.

---

## 12) 요약

* 함의 `P → Q`는 **오직 (T, F)에서만 거짓**
* 대우 `¬Q → ¬P`는 **원명제와 동치**
* 역 `Q → P`와 이 `¬P → ¬Q`는 **서로 동치**
* 쌍조건 `P ↔ Q`는 **P와 Q가 같은 값일 때만 참**
* `P ↔ Q ≡ (P → Q) ∧ (Q → P)`
