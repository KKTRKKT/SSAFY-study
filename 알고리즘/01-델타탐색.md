## 1. 문제 상황 요약

현재 위치가 `(x, y)`일 때, **정수 하나(`dir_num`)**가 주어지고
그 값에 따라 **상하좌우 중 한 칸** 이동해야 합니다.

방향 규칙은 다음과 같습니다.

| dir_num | 의미 | 이동    |
| ------- | -- | ----- |
| 0       | 동쪽 | x + 1 |
| 1       | 남쪽 | y - 1 |
| 2       | 서쪽 | x - 1 |
| 3       | 북쪽 | y + 1 |

---

## 2. 가장 직관적인 풀이의 문제점

처음에는 보통 다음과 같은 `if / elif` 구조를 떠올립니다.

```python
if dir_num == 0:
    nx, ny = x + 1, y
elif dir_num == 1:
    nx, ny = x, y - 1
elif dir_num == 2:
    nx, ny = x - 1, y
else:
    nx, ny = x, y + 1
```

### 문제점

* **같은 구조의 코드가 반복**됨
* 방향이 늘어나면(`대각선`, `8방향` 등) 분기문이 급격히 증가
* 실수하기 쉽고, 수정 비용이 큼

즉, **방향마다 좌표 변화만 다른데 로직은 전부 중복**입니다.

---

## 3. 핵심 아이디어: “방향 = 좌표 변화”

이 문제를 단순화하는 핵심은 다음 한 문장입니다.

> **각 방향은 `(x 변화량, y 변화량)`으로 표현할 수 있다**

이를 표로 바꾸면 다음과 같습니다.

| 방향   | dx | dy |
| ---- | -- | -- |
| 동(0) | +1 | 0  |
| 남(1) | 0  | -1 |
| 서(2) | -1 | 0  |
| 북(3) | 0  | +1 |

이 값을 **배열로 저장**합니다.

```python
dx = [ 1,  0, -1,  0]
dy = [ 0, -1,  0,  1]
```

* `dx[i]`, `dy[i]`는 **i번 방향으로 한 칸 이동했을 때의 변화량**
* `dir_num`을 그대로 **배열 인덱스**로 사용

## 4. dx, dy를 사용한 최종 코드

이제 분기문은 완전히 사라집니다.

```python
nx = x + dx[dir_num]
ny = y + dy[dir_num]
```

### 왜 이게 가능한가?

* `dir_num == 2` (서쪽)일 때
  → `dx[2] = -1`, `dy[2] = 0`
* 즉, **x만 1 감소, y는 그대로**
* 방향에 따른 처리를 **데이터로 표현**했기 때문

---

## 5. dx, dy 테크닉의 장점

### 1️⃣ 코드가 짧고 명확해짐

* 조건문 제거
* 한 줄로 이동 처리 가능

### 2️⃣ 확장성이 매우 좋음

예를 들어 **8방향 이동**도 배열만 바꾸면 끝입니다.

```python
dx = [1, 1, 0, -1, -1, -1, 0, 1]
dy = [0, 1, 1,  1,  0, -1,-1,-1]
```

### 3️⃣ 실전 문제에서 거의 표준

* BFS / DFS
* 시뮬레이션
* 미로 탐색
* 로봇 이동 문제

→ **알고리즘 문제에서는 사실상 필수 패턴**

---

## 6. 한 문장으로 정리

> **dx, dy 테크닉은 “방향에 따른 좌표 변화를 코드가 아니라 데이터로 관리하는 방법”이다**

이 방식에 익숙해지면

* 조건문이 줄어들고
* 버그가 감소하며
* 복잡한 이동 로직도 단순하게 표현할 수 있습니다.
